# OrangeHRM Test Plan

## 1. Introduction

This document describes the testing strategy, objectives, scope, resources, schedule, and deliverables for the OrangeHRM Demo application. The purpose of testing is to verify that the application's features work as expected and to identify defects before deployment.

## 2. Project Information

Project Name: OrangeHRM Manual Testing

Application: OrangeHRM Demo

Application URL: https://opensource-demo.orangehrmlive.com/

Testing Type: Manual Testing

Platform: Web Application

Browser: Google Chrome

## 3. Objectives

The objectives of this testing project are to:

* Verify that application features work according to the expected behavior.
* Identify functional defects.
* Validate input fields and error handling.
* Ensure the user interface is consistent and user friendly.
* Document defects with sufficient details for developers.
* Produce testing documentation following the Software Testing Life Cycle (STLC).

## 4. Scope

### In Scope

The following modules will be tested:

* Login
* Dashboard
* Admin
* PIM
* Leave
* Recruitment
* My Info

### Out of Scope

The following areas are not covered:

* Performance Testing
* Load Testing
* Security Testing
* API Testing
* Mobile Application Testing
* Database Testing

## 5. Testing Types

The following testing techniques will be performed:

* Smoke Testing
* Functional Testing
* UI Testing
* Regression Testing
* Positive Testing
* Negative Testing
* Boundary Value Analysis
* Equivalence Partitioning
* Exploratory Testing

## 7. Entry Criteria

Testing will begin when:

* Test environment is available.
* Application is accessible.
* Test data is prepared.
* Test cases are reviewed.

## 8. Exit Criteria

Testing will be completed when:

* All planned test cases are executed.
* Critical defects are documented.
* Test execution report is completed.
* Test summary report is prepared.

## 9. Test Deliverables

The project will include:

* Test Plan
* Test Scenarios
* Test Cases
* Bug Report
* Screenshots
* Requirement Traceability Matrix (RTM)
* Test Execution Report
* Test Summary Report

## 10. Defect Severity

### Critical

Application crashes or users cannot continue.

### High

Core functionality does not work.

### Medium

Feature works incorrectly but has a workaround.

### Low

Minor UI or cosmetic issue.

## 11. Defect Priority

High

Issue should be fixed immediately.

Medium

Issue should be fixed before release.

Low

Issue has minimal impact on users.

## 12. Risks

* Changes to application functionality during testing.
* Limited testing time.
* Browser compatibility issues.
* Temporary server downtime.

## 13. Assumptions

* Test environment remains available.
* Internet connection remains stable.
* Test credentials remain valid.
* Application behavior remains consistent during testing.
